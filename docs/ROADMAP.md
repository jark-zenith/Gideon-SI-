# GIDEON SI Roadmap

## Phase 0 — Foundation
Architecture, security model, agent instructions, ADRs and repository conventions.
Done when the engineering blueprint is committed and reviewed.

## Phase 1 — GIDEON Core
Create the backend/core contracts, provider interface, session model and structured response format.
Done when a provider can answer through the core with tests.

## Phase 2 — Web Application
Authenticated web shell, conversation UI and server API.
Done when a user can sign in and have a real text conversation.

## Phase 3 — AI Conversation
Context handling, error states, model adapter and initial observability.
Done when conversation is reliable and no fake results are presented.

## Phase 4 — Voice
Push-to-talk STT and TTS with idle/listening/thinking/speaking states.
Done when a user can complete a real voice turn.

## Phase 5 — Holographic Interface
Original GIDEON visual system based on the repository reference asset.
Done when the UI reflects real assistant states rather than simulated intelligence.

## Phase 6 — Memory
User-controlled short/long-term and project memory, with isolation and deletion.
Done when memory can be inspected and removed by the owner.

## Phase 7 — GitHub Tools
Read-only repository inspection with policy checks and audit logs.
Done when GIDEON can inspect an authorized repository and report real findings.

## Phase 8 — Agent Workflows
Controlled multi-step workflows with approval gates.
Done only after strong evaluation and security testing.

## Phase 9 — Android/Desktop
Shared backend integrations and permissioned device capabilities.
Done per platform security constraints.

## Phase 10 — Wake Word
Evaluate local wake-word detection, privacy and battery impact before implementation.

## Phase 11 — Advanced GIDEON SI
Realtime voice, richer multimodal capabilities, model routing and advanced agents.

Each phase must preserve the no-fake-functionality rule.
